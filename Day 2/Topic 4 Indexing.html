#14

VectorStoreIndex — Core RAG Index

The most-used index in LlamaIndex. It takes your nodes, embeds them, and stores them in a vector store. At query time, it embeds the question and finds the most similar nodes via cosine similarity.

How it works

→
Nodes (chunks)
→
Embed
→
VectorStore
→
QueryEngine
Build from documents (in-memory)
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

documents = SimpleDirectoryReader("./data").load_data()

# Chunks + embeds + stores automatically
index = VectorStoreIndex.from_documents(documents)

# Create query engine from index
query_engine = index.as_query_engine()
Build from pre-processed nodes
# Use when you ran an IngestionPipeline first
index = VectorStoreIndex(nodes)

# With an external vector store (e.g. Qdrant)
index = VectorStoreIndex.from_vector_store(vector_store)
✅ from_documents() is great for prototyping. In production, always use an external vector store (Topic 5) so data persists and scales.
#15

Document Management — Add, Delete, Refresh

Production indexes need to stay up to date. LlamaIndex provides methods to insert, delete, and refresh documents without rebuilding the entire index.

Insert new documents
from llama_index.core import Document

new_doc = Document(text="New content here...")

# Insert into existing index
index.insert(new_doc)
Delete documents
# Delete by document ID
index.delete_ref_doc("doc_id_here", delete_from_docstore=True)
Refresh — update changed documents
# Re-indexes only docs whose content changed
refreshed_docs = index.refresh_ref_docs(
    updated_documents,
    update_kwargs={"delete_kwargs": {"delete_from_docstore": True}}
)

#16

Metadata Filtering During Indexing

Tag your nodes with metadata at ingestion time, then filter by it at query time. This is how you build multi-tenant systems, date-range queries, and department-specific knowledge bases.

Set metadata on documents
from llama_index.core import Document

doc = Document(
    text="Q3 financial results...",
    metadata={
        "department": "finance",
        "year": 2024,
        "quarter": "Q3",
        "user_id": "tenant_42"
    }
)
Filter at query time
from llama_index.core.vector_stores import (
    MetadataFilter, MetadataFilters, FilterOperator
)

filters = MetadataFilters(filters=[
    MetadataFilter(key="department", value="finance"),
    MetadataFilter(key="year", value=2024, operator=FilterOperator.EQ),
])

query_engine = index.as_query_engine(filters=filters)
response = await query_engine.aquery("What were the Q3 results?")
🔒 For multi-tenant apps, always filter by user_id at query time. This prevents users from retrieving each other's data.

Property Graph Index — Knowledge Graph RAG

Instead of just embedding chunks, a Property Graph Index extracts entities and relationships from your documents and builds a knowledge graph. Enables multi-hop reasoning — e.g. "Who is the CEO of the company that acquired Acme?"

──used_in──▶
RAG System

Entities → Relationships → Concepts extracted from documents

Code
from llama_index.core import PropertyGraphIndex

index = PropertyGraphIndex.from_documents(
    documents,
    # LLM extracts entities + relationships
    show_progress=True
)

query_engine = index.as_query_engine(
    include_text=True  # include source text with graph results
)
⚠️ Graph extraction uses many LLM calls — expensive on large corpora. Best for complex relationship-heavy domains: legal, medical, research literature.

#18

Persistent Storage — Save & Load Index

In-memory indexes are lost on restart. Persist them to disk (or an external vector DB) so you don't re-embed every time the app starts. This is essential for production.

Save index to disk
from llama_index.core import StorageContext

# Build index as usual
index = VectorStoreIndex.from_documents(documents)

# Persist to directory
index.storage_context.persist(persist_dir="./storage")
Load index from disk
from llama_index.core import load_index_from_storage, StorageContext

# Reload — no re-embedding needed
storage_context = StorageContext.from_defaults(persist_dir="./storage")
index = load_index_from_storage(storage_context)

query_engine = index.as_query_engine()
What gets saved
docstore.json
All Document and Node objects
index_store.json
Index metadata and structure
vector_store.json
Embeddings (only for in-memory / SimpleVectorStore)
graph_store.json
Knowledge graph data (if PropertyGraphIndex)
💡 For production, skip disk persistence and use an external vector store (Pinecone, Qdrant, etc.) — covered in Topic 5. The vector store handles persistence natively.
