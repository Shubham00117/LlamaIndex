Installation & Project Structure

LlamaIndex is split into a lean core package plus optional integration packages. Always install only what you need to avoid bloat.

Install
# Core — always needed
pip install llama-index-core

# LLM integration (pick yours)
pip install llama-index-llms-openai
pip install llama-index-llms-anthropic

# Embedding integration
pip install llama-index-embeddings-openai

# Vector store (e.g. Qdrant)
pip install llama-index-vector-stores-qdrant
Recommended project structure
my_rag_app/
├── main.py          # entry point
├── ingestion.py     # load + index docs
├── query.py         # query engine logic
├── config.py        # Settings, env vars
├── data/            # raw source documents
├── storage/         # persisted index
└── .env             # API keys
llama-index-core modular installs separation of concerns
#2

Settings Configuration

Settings is a global singleton. Set it once at startup — all indexes, query engines, and pipelines pick it up automatically. No need to pass LLM/embed objects everywhere.

Code
from llama_index.core import Settings
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding

# Set global LLM
Settings.llm = OpenAI(model="gpt-4o", temperature=0.1)

# Set global embedding model
Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")

# Chunk size & overlap (tune per project)
Settings.chunk_size = 512
Settings.chunk_overlap = 50
Key settings explained
Settings.llm
The LLM used for generation, reranking, and agents
Settings.embed_model
Embedding model used during indexing and querying
Settings.chunk_size
Token size per chunk — smaller = precise, larger = context-rich
Settings.chunk_overlap
Overlap between chunks — avoids cutting off context at boundaries
💡 Start with chunk_size=512, overlap=50 for most RAG projects. Tune based on evaluation results later.
#3

Async Programming Basics

Production LlamaIndex is almost entirely async. Query engines, ingestion pipelines, agents, and workflows all expose aquery() / arun() async variants. Always use them in FastAPI and workflow contexts.

Sync vs Async query
# ❌ Sync — blocks the event loop (avoid in APIs)
response = query_engine.query("What is RAG?")

# ✅ Async — non-blocking (use in production)
response = await query_engine.aquery("What is RAG?")
FastAPI integration pattern
from fastapi import FastAPI

app = FastAPI()

@app.get("/query")
async def query_endpoint(q: str):
    response = await query_engine.aquery(q)
    return {"answer": str(response)}
Common async methods
aquery()
Async query on QueryEngine
achat()
Async chat on ChatEngine
arun()
Async run for Agents & Workflows
aload_data()
Async document loading
⚡ Use asyncio.run() when calling async code from a plain Python script outside of FastAPI or a running event loop.
