#67

ReAct Agent Pattern

ReAct (Reason + Act) is the foundational agent pattern. The LLM alternates between Thought (reasoning), Action (tool call), and Observation (tool result) until it reaches an answer. Works with any LLM, no function-calling required.

ReAct loop — example trace
THOUGHT
I need to find the Q3 revenue. Let me search the financial documents.
ACTION
search_docs(query="Q3 revenue 2024")
OBSERVATION
Q3 2024 revenue was $4.2M, up 18% from Q2 ($3.56M).
THOUGHT
I have the Q3 revenue. I can now calculate the YoY growth if needed, or answer directly.
ANSWER
Q3 2024 revenue was $4.2M, representing 18% growth over Q2.
Setup
from llama_index.core.agent import ReActAgent
from llama_index.core.tools import QueryEngineTool
from llama_index.llms.openai import OpenAI

# Wrap your query engine as a tool
rag_tool = QueryEngineTool.from_defaults(
    query_engine=query_engine,
    name="search_docs",
    description="Search company documents for financial and operational info"
)

# Create ReAct agent
agent = ReActAgent.from_tools(
    tools=[rag_tool],
    llm=OpenAI(model="gpt-4o"),
    verbose=True,
    max_iterations=10   # safety limit
)

response = await agent.achat("What was our Q3 revenue and how does it compare to Q2?")
💡 ReAct works with any LLM (including local models via Ollama). Use FunctionCallingAgent (#68) instead when your LLM supports native function calling — it's more reliable.
#68

FunctionCalling Agent

Uses the LLM's native function/tool-calling API (OpenAI, Anthropic, Gemini, Groq) instead of text-based ReAct reasoning. More reliable, faster, and produces cleaner tool calls — the production standard for capable LLMs.

Setup
from llama_index.core.agent import FunctionCallingAgent
from llama_index.core.tools import FunctionTool

# Define a simple Python function as a tool
def get_weather(city: str) -> str:
    """Returns current weather for the given city."""
    return fetch_weather_api(city)

weather_tool = FunctionTool.from_defaults(fn=get_weather)
rag_tool     = QueryEngineTool.from_defaults(
    query_engine=query_engine,
    name="search_knowledge_base",
    description="Search the internal knowledge base"
)

agent = FunctionCallingAgent.from_tools(
    tools=[weather_tool, rag_tool],
    llm=OpenAI(model="gpt-4o"),
    verbose=True
)

response = await agent.achat(
    "What's the weather in our London office city, and what does our travel policy say?"
)
ReActAgent
Text-based reasoning loop. Works with any LLM including local ones.
FunctionCallingAgent
Native tool-calling API. More reliable, structured. Requires capable LLM.
#69

Building Custom Tools for Agents

Agents are only as powerful as their tools. You can wrap any Python function, API call, or database query as a tool. The docstring becomes the tool description — write it clearly so the LLM knows when to use it.

Built-in tool types
🔍
QueryEngineTool
Wraps a VectorStoreIndex query engine as a searchable tool.
⚡
FunctionTool
Wraps any Python function. Docstring = tool description.
🗄️
RetrieverTool
Wraps a retriever directly — returns nodes, not synthesized answers.
FunctionTool — wrapping a Python function
from llama_index.core.tools import FunctionTool

def calculate_roi(investment: float, returns: float) -> str:
    """
    Calculate Return on Investment (ROI).
    Args:
        investment: Initial investment amount in dollars
        returns: Total returns received in dollars
    Returns:
        ROI as a percentage string
    """
    roi = ((returns - investment) / investment) * 100
    return f"ROI: {roi:.2f}%"

roi_tool = FunctionTool.from_defaults(fn=calculate_roi)

# Async functions work too
async def fetch_stock_price(ticker: str) -> str:
    """Fetch the current stock price for a given ticker symbol."""
    price = await stock_api.get_price(ticker)
    return f"{ticker}: ${price}"

stock_tool = FunctionTool.from_defaults(async_fn=fetch_stock_price)
📝 The docstring IS the tool description — write it clearly. The LLM reads it to decide when and how to call the tool. Poor docstrings = wrong tool usage.
#70

Agent Memory — Short-Term & Long-Term

Agents need two kinds of memory: short-term (within a session) and long-term (across sessions). Without proper memory, agents repeat work and lose context between conversations.

🧠 Short-Term (In-session)
from llama_index.core.memory import ChatMemoryBuffer

# Agent retains full conversation
# within the current session
memory = ChatMemoryBuffer.from_defaults(
    token_limit=4000
)

agent = ReActAgent.from_tools(
    tools=tools,
    memory=memory
)

# Session 1
agent.chat("My name is Alice")
agent.chat("What's my name?")
# → "Your name is Alice"  ✅
💾 Long-Term (Cross-session)
# Store facts agent learned
# in a vector index for retrieval

from llama_index.core.memory import VectorMemory

vector_memory = VectorMemory.from_defaults(
    vector_store=vector_store,   # persisted store
    embed_model=OpenAIEmbedding()
)

# Add key facts to long-term memory
vector_memory.put(
    ChatMessage(role="user",
        content="User prefers formal English")
)

# Survives restarts — recalled
# at next session via similarity search
💡 Combine ChatMemoryBuffer (recent turns) with VectorMemory (facts from past sessions) using SimpleComposableMemory for production agents that learn over time.

Multi-Agent Patterns & Human-in-the-Loop

Complex tasks benefit from specialized sub-agents coordinated by an orchestrator agent. Each sub-agent has its own tools and focus area — divide and conquer.

Multi-agent architecture (#71)
🧠 Orchestrator Agent
↙ ↓ ↘
📊 Finance Agent
earnings, forecasts
⚖️ Legal Agent
contracts, compliance
🔍 Research Agent
market data, news
# Each sub-agent becomes a tool for the orchestrator
finance_agent  = ReActAgent.from_tools([finance_tool],  llm=llm)
legal_agent    = ReActAgent.from_tools([legal_tool],    llm=llm)
research_agent = ReActAgent.from_tools([research_tool], llm=llm)

# Wrap each as a tool
finance_tool_ag  = QueryEngineTool.from_defaults(
    query_engine=finance_agent.as_query_engine(),
    name="finance_expert",
    description="Expert on financial data and earnings reports"
)

# Orchestrator delegates to sub-agents
orchestrator = ReActAgent.from_tools(
    [finance_tool_ag, legal_tool_ag, research_tool_ag],
    llm=OpenAI(model="gpt-4o")
)
Human-in-the-Loop (#72)
from llama_index.core.agent import ReActAgent

# Tool that pauses for human approval
def approve_and_send_email(recipient: str, body: str) -> str:
    """Draft and send an email after human approval."""
    print(f"\n📧 DRAFT EMAIL TO: {recipient}\n{body}\n")
    confirm = input("Send this email? (yes/no): ")
    if confirm.lower() == "yes":
        send_email(recipient, body)
        return "Email sent successfully."
    return "Email cancelled by user."

hitl_tool = FunctionTool.from_defaults(fn=approve_and_send_email)
🛡️ Always use HITL for irreversible actions — sending emails, making purchases, deleting data, calling external APIs with side effects. Agents make mistakes; humans catch them.

Structured Output from Agents & Streaming Events

Force agents to return typed Pydantic objects at the end of their reasoning loop, and stream intermediate agent events to the frontend for real-time progress updates.

Structured agent output (#73)
from pydantic import BaseModel
from llama_index.core.agent import StructuredPlannerAgent

class ResearchReport(BaseModel):
    summary:     str
    key_findings: List[str]
    confidence:  float
    sources:     List[str]

# Agent reasons freely, returns structured output
agent = ReActAgent.from_tools(tools=tools, llm=llm)

# Use structured_predict at the end
raw_response = await agent.achat("Research the EV market trends")
report: ResearchReport = llm.structured_predict(
    ResearchReport,
    PromptTemplate("Structure this research:\n\n{text}"),
    text=str(raw_response)
)
Streaming agent events (#74)
from llama_index.core.agent import AgentRunner

agent = ReActAgent.from_tools(tools=tools, llm=llm)

# Stream step-by-step events
handler = agent.stream_chat(
    "Analyze our Q3 performance and compare to competitors"
)

for token in handler.response_gen:
    print(token, end="")

# Or use async streaming with step callbacks
async def stream_agent_events(query: str):
    handler = await agent.astream_chat(query)
    async for event in handler.async_response_gen():
        # Send to frontend via WebSocket or SSE
        await websocket.send_text(event)
⚡ Stream agent events to your frontend so users see the agent thinking and acting in real time — much better UX than a blank screen while the agent works for 30 seconds.
Agent quick-reference
ReActAgent
Text-based reasoning. Works with any LLM. Good default.
FunctionCallingAgent
Native tool calling. More reliable. Use with GPT-4o, Claude, Gemini.
Multi-agent
Orchestrator + specialized sub-agents. Scale to complex tasks.
HITL
Human approval gate. Always use for irreversible actions.
Structured output
Force Pydantic schema on agent's final answer.
Streaming events
Real-time step visibility for frontend UX.
