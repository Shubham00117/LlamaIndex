Why Re-ranking Matters

Vector similarity retrieves nodes that are semantically close to the query — but similarity ≠ relevance. A reranker is a second-pass model that scores (query, chunk) pairs directly, dramatically improving the quality of what gets sent to the LLM.

🏆 Reranking is the single highest-impact improvement you can make to a RAG pipeline. It consistently boosts answer quality by 20–40% in evaluations. Always use one in production.
#53

Cohere Reranker

Cohere's reranker is a cross-encoder model accessed via API. It's the easiest production reranker to set up — no GPU needed, just an API key. Excellent quality, especially for multilingual content.

Setup & usage
pip install llama-index-postprocessor-cohere-rerank

from llama_index.postprocessor.cohere_rerank import CohereRerank
from llama_index.core.query_engine import RetrieverQueryEngine

# Create reranker
cohere_rerank = CohereRerank(
    api_key="YOUR_COHERE_KEY",
    top_n=3   # return top 3 after reranking
)

# Retrieve more, rerank down to fewer
retriever = index.as_retriever(similarity_top_k=20)

query_engine = RetrieverQueryEngine(
    retriever=retriever,
    node_postprocessors=[cohere_rerank]   # runs after retrieval
)

response = await query_engine.aquery("What are the key findings?")
rerank-english-v3.0
Best for English content. Highest quality Cohere reranker.
rerank-multilingual-v3.0
Supports 100+ languages. Use for international deployments.
rerank-english-v2.0
Older model. Avoid for new projects — v3 is strictly better.
💡 The pattern: retrieve 15–20, rerank to top 3–5. The reranker is fast — the extra retrieval cost is worth the quality gain.
#54

BGE Reranker — Local (Free)

BGE (BAAI General Embedding) rerankers run locally via HuggingFace — zero API cost. Slightly slower than Cohere but competitive quality, especially bge-reranker-large. Best for cost-sensitive or data-private setups.

Setup & usage
pip install llama-index-postprocessor-flag-embedding-reranker

from llama_index.postprocessor.flag_embedding_reranker import FlagEmbeddingReranker

# Downloads model on first use (~1GB for large)
reranker = FlagEmbeddingReranker(
    model="BAAI/bge-reranker-large",
    top_n=3
)

query_engine = RetrieverQueryEngine(
    retriever=index.as_retriever(similarity_top_k=15),
    node_postprocessors=[reranker]
)

~1.3GB · Best quality local reranker · Production default

Multilingual, lightweight · Good Cohere alternative for multi-language
💰 BGE reranker has zero per-query cost. For 100K+ daily queries, it saves hundreds of dollars/month vs Cohere API. Requires GPU for good throughput.
#55

LLM-Based Reranking

Use an LLM itself to score relevance. Slower and more expensive than dedicated rerankers, but can understand nuanced domain-specific relevance that cross-encoders miss. Best for complex legal, medical, or technical content.

LLM Rerank — built into LlamaIndex
from llama_index.core.postprocessor import LLMRerank

llm_reranker = LLMRerank(
    choice_batch_size=5,   # score 5 nodes per LLM call
    top_n=3               # return top 3
)

query_engine = RetrieverQueryEngine(
    retriever=index.as_retriever(similarity_top_k=10),
    node_postprocessors=[llm_reranker]
)
How it works internally
# LlamaIndex prompts the LLM with something like:
#
# Query: "What are the side effects of drug X?"
# Passage 1: "Drug X is used for treating..."
# Passage 2: "Side effects include nausea, headache..."
# Passage 3: "The dosage of drug X is..."
#
# Which passages best answer the query? Rank them.
# LLM returns: [2, 1, 3]
⚠️ LLM reranking uses multiple LLM calls per query — can be 3–10× more expensive than Cohere rerank. Use it only when domain-specific nuance is critical and you've validated the cost.
#56

MMR — Maximum Marginal Relevance

Standard retrieval often returns very similar chunks — e.g. the same paragraph from 3 slightly different angles. MMR balances relevance with diversity: each new result must be both relevant to the query and different from already-selected results.

The MMR formula (simplified)
# MMR score = λ × relevance(doc, query)
#           - (1-λ) × max_similarity(doc, already_selected)
#
# λ=1.0 → pure relevance (same as standard retrieval)
# λ=0.0 → pure diversity
# λ=0.5 → balanced (typical production value)
Usage in LlamaIndex
from llama_index.core.postprocessor import MMRNodePostprocessor

mmr_postprocessor = MMRNodePostprocessor(
    similarity_cutoff=0.7,   # minimum relevance to include
    mmr_threshold=0.5        # λ — balance relevance vs diversity
)

query_engine = RetrieverQueryEngine(
    retriever=index.as_retriever(similarity_top_k=10),
    node_postprocessors=[mmr_postprocessor]
)
mmr_threshold = 0.7
Lean towards relevance. Use for precise factual Q&A.
mmr_threshold = 0.5
Balanced default. Good for general research queries.
mmr_threshold = 0.3
Lean towards diversity. Use for broad topic exploration.
🌈 Use MMR when responses feel repetitive or keep citing the same section of a document. It ensures the LLM gets diverse context to synthesize a richer answer.
