Query Engine — Basics & Response Modes

The QueryEngine is the top-level interface that takes a question, retrieves relevant nodes, and synthesizes an answer using the LLM. It combines a Retriever + Response Synthesizer in one.

Basic usage
# Build query engine from index
query_engine = index.as_query_engine(
    similarity_top_k=5,           # retrieve top 5 nodes
    response_mode="compact"        # response synthesis mode
)

# Sync query
response = query_engine.query("What is RAG?")
print(response.response)          # answer text
print(response.source_nodes)      # source chunks used

# Async query (use in FastAPI)
response = await query_engine.aquery("What is RAG?")
Response modes explained
compact
Default. Stuffs all retrieved nodes into one prompt. Fast & cheap.
refine
Generates then refines answer iteratively over each node. Slower but thorough.
tree_summarize
Builds a tree of summaries. Best for large doc sets / summarization tasks.
simple_summarize
Single prompt with truncation. Use for quick summaries with context limits.
no_text
Returns retrieved nodes only — no LLM synthesis. Useful for debugging.
Streaming responses (#42)
# Enable streaming
query_engine = index.as_query_engine(streaming=True)

response = query_engine.query("Summarize the document")

# Stream tokens as they arrive
response.print_response_stream()

# Or iterate manually for FastAPI SSE
for token in response.response_gen:
    print(token, end="", flush=True)
💡 Start with response_mode="compact" and top_k=3–5. Only increase if evaluation shows missing context. More nodes = more cost.

Metadata Filtering & Top-k Tuning

Metadata filters narrow retrieval to relevant subsets before vector search. Top-k and similarity thresholds control how many and how relevant nodes must be to be returned.

Metadata filtering at query time
from llama_index.core.vector_stores import (
    MetadataFilter, MetadataFilters, FilterCondition
)

filters = MetadataFilters(
    filters=[
        MetadataFilter(key="department", value="engineering"),
        MetadataFilter(key="year", value=2024),
    ],
    condition=FilterCondition.AND   # AND or OR
)

query_engine = index.as_query_engine(
    filters=filters,
    similarity_top_k=5
)
Top-k and similarity threshold
# Basic top-k — return 5 most similar nodes
retriever = index.as_retriever(similarity_top_k=5)

# With similarity cutoff — ignore low-quality matches
from llama_index.core.retrievers import VectorIndexRetriever

retriever = VectorIndexRetriever(
    index=index,
    similarity_top_k=10,
    node_ids=None,
)
# Then post-filter by score threshold manually
nodes = [n for n in nodes if n.score > 0.75]
top_k = 3
Precise, less noise, lower cost. Use for factual Q&A.
top_k = 5–10
Balanced. Good for most RAG use cases.
top_k = 20+
Use with reranker to reduce to top 3–5 after retrieval.
score threshold
0.7–0.8 is typical. Below 0.6 often means no relevant content found.

BM25 Retriever & Hybrid Search

Vector search excels at semantic queries but fails on exact keywords, product codes, and names. BM25 handles keywords well but misses semantic meaning. Hybrid combines both.

# Build BM25 retriever from existing nodes
bm25_retriever = BM25Retriever.from_defaults(
    nodes=nodes,
    similarity_top_k=5
)
Hybrid Search — BM25 + Vector
from llama_index.core.retrievers import QueryFusionRetriever

vector_retriever = index.as_retriever(similarity_top_k=5)
bm25_retriever  = BM25Retriever.from_defaults(nodes=nodes, similarity_top_k=5)

hybrid_retriever = QueryFusionRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    similarity_top_k=5,
    num_queries=1,            # don't generate extra queries
    mode="reciprocal_rerank"  # RRF fusion
)
✅ Hybrid search is the production default for most enterprise RAG. Always use it unless your queries are purely semantic with no exact-match needs.

Auto-Merging & Recursive Retriever

Two of the most powerful production retrieval patterns. Both use parent-child chunk relationships to retrieve small precise chunks but return larger context to the LLM.

⬆️ Auto-Merging Retriever (#47)

Retrieve small leaf chunks → if enough leaf chunks from the same parent are retrieved → return the parent chunk instead. Avoids fragmented context.

from llama_index.core.node_parser import HierarchicalNodeParser
from llama_index.core.retrievers import AutoMergingRetriever
from llama_index.core.storage.docstore import SimpleDocumentStore

# 1. Create hierarchical nodes
parser = HierarchicalNodeParser.from_defaults(
    chunk_sizes=[512, 128]
)
nodes = parser.get_nodes_from_documents(docs)

# 2. Store ALL nodes (parent + leaf)
docstore = SimpleDocumentStore()
docstore.add_documents(nodes)

# 3. Index only leaf nodes
leaf_nodes = [n for n in nodes if isinstance(n, IndexNode)]
index = VectorStoreIndex(leaf_nodes)

# 4. Wrap with auto-merging retriever
base_retriever = index.as_retriever(similarity_top_k=6)
retriever = AutoMergingRetriever(
    base_retriever,
    storage_context=storage_context
)
🔗 Recursive Retriever (#48)

Index small summary chunks → on retrieval, follow node references to load the full parent content. Good for structured docs with sections.

from llama_index.core.retrievers import RecursiveRetriever
from llama_index.core.schema import IndexNode

# Create child nodes that reference parents
index_nodes = []
for n in nodes:
    index_node = IndexNode(
        text=n.get_content(metadata_mode="all")[:128],
        index_id=n.node_id
    )
    index_nodes.append(index_node)

# Index the small summaries
index = VectorStoreIndex(index_nodes)

# Recursive retriever follows references
retriever = RecursiveRetriever(
    "vector",
    retriever_dict={"vector": index.as_retriever()},
    node_dict={n.node_id: n for n in nodes}
)
🏆 Auto-Merging Retriever is one of the highest-performing RAG patterns on benchmarks. Embed small → return large = precise retrieval + rich context for LLM.

Query Fusion & Reciprocal Rerank Fusion

Query Fusion generates multiple variations of the user's query, retrieves for each, then merges results. This dramatically improves recall when a single query misses relevant content.

Query Fusion Retriever (#49)
from llama_index.core.retrievers import QueryFusionRetriever

retriever = QueryFusionRetriever(
    retrievers=[vector_retriever],
    similarity_top_k=5,
    num_queries=4,         # LLM generates 4 query variations
    mode="reciprocal_rerank",
    use_async=True,
    verbose=True
)
# User query: "What causes inflation?"
# Generated: "factors leading to inflation", "inflation causes",
#            "why does inflation happen", "monetary inflation drivers"
Reciprocal Rerank Fusion (RRF) (#50)
# RRF combines ranked lists from multiple retrievers
# Each doc gets score: sum(1 / (rank + k)) across all lists
# k=60 is the standard constant

retriever = QueryFusionRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    mode="reciprocal_rerank",  # RRF fusion mode
    similarity_top_k=5,
    num_queries=1             # no extra query gen — pure RRF
)
🔄 RRF is fusion math, not ML — it's fast, deterministic, and doesn't require training. It consistently outperforms single-retriever setups in benchmarks.

Router Retriever & Auto-Retrieval

These two patterns let the LLM itself decide how to retrieve — either routing to the right data source or automatically constructing the right metadata filter for the query.

Router Retriever (#51) — route queries to the right index
from llama_index.core.selectors import LLMSingleSelector
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.tools import QueryEngineTool

# Two separate indexes
finance_tool = QueryEngineTool.from_defaults(
    query_engine=finance_engine,
    description="Use for questions about financial reports and earnings"
)
hr_tool = QueryEngineTool.from_defaults(
    query_engine=hr_engine,
    description="Use for HR policies, benefits and employee questions"
)

# LLM picks which engine to use
router_engine = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=[finance_tool, hr_tool]
)
Auto-Retrieval (#52) — LLM builds the filter
from llama_index.core.retrievers import VectorIndexAutoRetriever
from llama_index.core.vector_stores.types import MetadataInfo, VectorStoreInfo

# Tell the LLM what metadata fields exist
vector_store_info = VectorStoreInfo(
    content_info="Company documents and reports",
    metadata_info=[
        MetadataInfo(name="department", type="str", description="Department name"),
        MetadataInfo(name="year",       type="int", description="Year of document"),
    ]
)

retriever = VectorIndexAutoRetriever(
    index=index,
    vector_store_info=vector_store_info
)
# Query: "Show me 2024 finance reports"
# LLM auto-builds: filter={department:"finance", year:2024}
🤖 Auto-Retrieval is powerful but uses extra LLM calls per query. Use Router Retriever when you have clearly separated domains (HR vs Finance vs Legal).
