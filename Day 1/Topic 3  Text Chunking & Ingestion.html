SentenceSplitter & TokenTextSplitter

After loading documents, they must be split into smaller chunks (Nodes) before embedding. These two splitters are used in almost every project.

SentenceSplitter — respects sentence boundaries
from llama_index.core.node_parser import SentenceSplitter

splitter = SentenceSplitter(
    chunk_size=512,      # tokens per chunk
    chunk_overlap=50    # overlap between chunks
)
nodes = splitter.get_nodes_from_documents(documents)
TokenTextSplitter — strict token-count based
from llama_index.core.node_parser import TokenTextSplitter

splitter = TokenTextSplitter(
    chunk_size=256,
    chunk_overlap=20
)
SentenceSplitter
Preferred for natural text. Splits on sentences — avoids cutting mid-sentence
TokenTextSplitter
Strict token count. Better for code, tables, structured text
✅ Default starting point: chunk_size=512, chunk_overlap=50 with SentenceSplitter. Adjust based on your evaluation results.

#11

Ingestion Pipeline

The IngestionPipeline chains transformations (splitting, metadata extraction, embedding) into a single reusable pipeline. Its biggest production feature: incremental indexing — it caches processed nodes so re-running never re-embeds already-processed data.

Basic pipeline
from llama_index.core.ingestion import IngestionPipeline
from llama_index.core.node_parser import SentenceSplitter
from llama_index.embeddings.openai import OpenAIEmbedding

pipeline = IngestionPipeline(
    transformations=[
        SentenceSplitter(chunk_size=512, chunk_overlap=50),
        OpenAIEmbedding(),   # embeds each node
    ]
)
nodes = await pipeline.arun(documents=documents)
Incremental indexing — avoid re-embedding
from llama_index.core.storage.docstore import SimpleDocumentStore

pipeline = IngestionPipeline(
    transformations=[SentenceSplitter(), OpenAIEmbedding()],
    docstore=SimpleDocumentStore(),   # tracks processed docs
)

# First run — processes all docs
nodes = await pipeline.arun(documents=docs)

# Second run — only new/changed docs are processed
nodes = await pipeline.arun(documents=updated_docs)
⚡ Incremental ingestion is critical for production. Without it, every pipeline run re-embeds all documents, wasting money and time.
#12

Transformations in Ingestion Pipeline

Any step in the pipeline is a Transformation. They are composable and run in sequence. You can mix splitters, metadata extractors, and embedding models freely.

Full production pipeline example
from llama_index.core.extractors import (
    TitleExtractor,
    QuestionsAnsweredExtractor
)

pipeline = IngestionPipeline(
    transformations=[
        # Step 1 — split into chunks
        SentenceSplitter(chunk_size=512, chunk_overlap=50),

        # Step 2 — extract metadata via LLM
        TitleExtractor(),
        QuestionsAnsweredExtractor(questions=3),

        # Step 3 — embed
        OpenAIEmbedding(model="text-embedding-3-small"),
    ]
)
⚠️ LLM-based transformations (TitleExtractor, QuestionsAnsweredExtractor) cost tokens. Use them only when retrieval quality justifies the cost.

#13

Node Parsers — Chunking Strategies

Beyond basic splitters, LlamaIndex has specialized node parsers for different document types and retrieval strategies. Pick the right one for your content.

Parser Best For Key Feature
SentenceSplitter General text, articles Respects sentence boundaries
TokenTextSplitter Code, structured data Strict token-count splitting
HierarchicalNodeParser Parent-child retrieval Creates chunk hierarchy (512→128 tokens)
MarkdownNodeParser Markdown docs Splits on headers (H1, H2, H3)
JSONNodeParser JSON / API responses Splits on JSON structure
CodeSplitter Source code files Splits using AST — respects function/class scope
HierarchicalNodeParser example
from llama_index.core.node_parser import HierarchicalNodeParser

# Creates parent chunks (512) and child chunks (128)
parser = HierarchicalNodeParser.from_defaults(
    chunk_sizes=[512, 256, 128]
)
nodes = parser.get_nodes_from_documents(documents)
