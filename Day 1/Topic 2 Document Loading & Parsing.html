#4

SimpleDirectoryReader

The fastest way to load local files. Points to a folder and auto-detects file types. Used in almost every project for loading source documents.

PDF DOCX TXT CSV HTML MD
Code
from llama_index.core import SimpleDirectoryReader

# Load all files from a folder
documents = SimpleDirectoryReader(
    input_dir="./data"
).load_data()

# Load specific files only
documents = SimpleDirectoryReader(
    input_files=["./data/report.pdf", "./data/notes.txt"]
).load_data()

# Recursive — load from nested subdirectories
documents = SimpleDirectoryReader(
    input_dir="./data",
    recursive=True
).load_data()
✅ Each loaded file becomes a Document object with .text and .metadata (filename, page number, etc.) automatically populated.

LlamaHub Data Connectors

LlamaHub provides pre-built connectors for external data sources — cloud storage, wikis, CRMs, and more. Each is a separate pip install.

Common connectors
Google Drive
llama-index-readers-google
S3 / AWS
llama-index-readers-s3
SharePoint
llama-index-readers-microsoft-sharepoint
Confluence
llama-index-readers-confluence
OneDrive
llama-index-readers-microsoft-onedrive
Example — load from S3
from llama_index.readers.s3 import S3Reader

reader = S3Reader(
    bucket="my-company-docs",
    prefix="contracts/",
    aws_access_id="...",
    aws_access_secret="..."
)
documents = reader.load_data()
💡 All connectors return the same Document objects — so your indexing code stays the same regardless of the data source.
#6

LlamaParse — Complex PDF Parsing

Standard PDF readers fail on tables, multi-column layouts, and charts. LlamaParse is a cloud API that extracts these accurately — critical for financial, legal, and technical documents.

Install & usage
pip install llama-parse
from llama_parse import LlamaParse
import os

parser = LlamaParse(
    api_key=os.environ["LLAMA_CLOUD_API_KEY"],
    result_type="markdown",   # or "text"
    verbose=True
)

documents = await parser.aload_data("./report.pdf")
Result types
markdown
Best for tables, headers, structured content
text
Plain extracted text, simpler downstream processing
⚠️ LlamaParse requires a LlamaCloud API key (free tier available). Use it when SimpleDirectoryReader gives poor results on complex PDFs.
#7

Custom Document Loaders

When no connector exists for your data source (internal databases, APIs, proprietary formats), build your own by subclassing BaseReader.

Pattern
from llama_index.core.readers.base import BaseReader
from llama_index.core.schema import Document

class MyAPIReader(BaseReader):
    def load_data(self, **kwargs):
        # Fetch data from your source
        raw_data = fetch_from_internal_api()

        # Return list of Document objects
        return [
            Document(
                text=item["content"],
                metadata={"source": item["id"], "date": item["date"]}
            )
            for item in raw_data
        ]

#8

Documents & Nodes

These are the two core data structures in LlamaIndex. Understanding them is essential for any customization.

Document
A full source file (e.g. one PDF). Has .text, .metadata, and a .doc_id
Node (TextNode)
A chunk of a Document after splitting. What actually gets embedded and stored
.metadata
Dict of key-value pairs — used for filtering, tracking source, page, author, etc.
.relationships
Links between nodes (PREVIOUS, NEXT, PARENT, CHILD) for hierarchical retrieval
Creating manually
from llama_index.core.schema import Document, TextNode

doc = Document(
    text="LlamaIndex is a framework for building RAG apps.",
    metadata={"source": "docs", "author": "team"}
)

node = TextNode(
    text="LlamaIndex is a framework...",
    metadata={"page": 1}
)
#9

Metadata Extraction

Automatically extract structured metadata from documents using LLMs — titles, summaries, question hypotheses. This metadata improves retrieval quality significantly.

Common extractors
TitleExtractor
Extracts document title using LLM
SummaryExtractor
Generates a summary for each node/section
QuestionsAnsweredExtractor
Generates hypothetical questions the node answers — great for HyDE
KeywordExtractor
Extracts key terms for keyword-based filtering
Code
from llama_index.core.extractors import (
    TitleExtractor, QuestionsAnsweredExtractor
)
from llama_index.core.ingestion import IngestionPipeline

pipeline = IngestionPipeline(
    transformations=[
        TitleExtractor(),
        QuestionsAnsweredExtractor(questions=3),
    ]
)
nodes = await pipeline.arun(documents=documents)
💡 Metadata extraction calls your LLM per node — it adds cost & latency. Use it during ingestion (offline), not at query time.
