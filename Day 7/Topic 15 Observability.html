Callbacks & LlamaDebugHandler

LlamaIndex fires callback events at every stage of the pipeline — LLM calls, embeddings, retrieval, chunking. The LlamaDebugHandler captures all of them for inspection during development.

What a trace looks like
▶ query("What is our cash position?") 1.84s ↑ 892 tokens ↓ 143 tokens
retrieve() 0.31s
embed_query() — text-embedding-3-small 0.12s
vector_search(top_k=5) 0.19s
rerank() — cohere-rerank-v3 0.08s
synthesize() — gpt-4o 1.45s
text_qa_template rendered → 892 tokens
LLM completion → 143 tokens · $0.0031
Setup
from llama_index.core.callbacks import CallbackManager, LlamaDebugHandler
from llama_index.core import Settings

# Set up debug handler
debug_handler = LlamaDebugHandler(print_trace_on_end=True)
Settings.callback_manager = CallbackManager([debug_handler])

# Run any query — debug output printed automatically
response = query_engine.query("What is our cash position?")

# Inspect events programmatically
# All LLM calls with inputs and outputs
llm_pairs = debug_handler.get_llm_inputs_outputs()
for pair in llm_pairs:
    print("Prompt tokens:", pair[0].payload.get("serialized"))
    print("Response:",      pair[1].payload.get("response"))

# All events by type
events = debug_handler.get_events()  # returns all captured events
debug_handler.flush_event_logs()     # clear between queries
CBEventType.LLM
Every LLM call — prompt, response, token counts
CBEventType.EMBEDDING
Every embed call — text, model, latency
CBEventType.RETRIEVE
Retrieval calls — query, nodes returned, scores
CBEventType.SYNTHESIZE
Response synthesis — context sent, output generated
CBEventType.CHUNKING
Text splitting events — chunk sizes, overlap
🔧 Use LlamaDebugHandler during development to understand exactly what's happening inside your pipeline — prompts sent, tokens used, latency per step. Disable in production.

Token Counting & Cost Tracking

Every LLM and embedding call costs tokens (and money). The TokenCountingHandler accumulates exact token counts so you can estimate costs before and monitor spend in production.

Setup token counting
from llama_index.core.callbacks import TokenCountingHandler
import tiktoken

token_counter = TokenCountingHandler(
    tokenizer=tiktoken.encoding_for_model("gpt-4o").encode
)

Settings.callback_manager = CallbackManager([token_counter])

# Run queries...
response = query_engine.query("Summarize the annual report")

# Read token stats
print(f"LLM prompt tokens:     {token_counter.prompt_llm_token_count}")
print(f"LLM completion tokens: {token_counter.completion_llm_token_count}")
print(f"Embedding tokens:      {token_counter.total_embedding_token_count}")
print(f"Total LLM tokens:      {token_counter.total_llm_token_count}")

# Compute approximate cost (GPT-4o rates)
prompt_cost     = token_counter.prompt_llm_token_count     / 1_000_000 * 2.50
completion_cost = token_counter.completion_llm_token_count / 1_000_000 * 10.00
print(f"Estimated cost: ${prompt_cost + completion_cost:.5f}")

Tracing Tools — Phoenix, LangSmith & OpenTelemetry

Production observability requires a dedicated tracing backend that captures every query, retrieval, and LLM call with latency, token counts, and full payloads — visualized in a UI for debugging and monitoring.

🔥 Arize Phoenix Free / OSS
Purpose-built for LLM observability. Best LlamaIndex integration. Self-hosted or cloud. Visualizes traces, evals, token costs in real time.
pip install arize-phoenix openinference-instrumentation-llama-index

import phoenix as px
from openinference.instrumentation.llama_index import LlamaIndexInstrumentor
from opentelemetry.sdk.trace.export import SimpleSpanProcessor

# Launch Phoenix UI at localhost:6006
session = px.launch_app()

# Auto-instrument all LlamaIndex calls
LlamaIndexInstrumentor().instrument(
    tracer_provider=register(project_name="my-rag-app")
)

# All queries now traced automatically
🦜 LangSmith Paid
LangChain's tracing platform. Works with LlamaIndex via OpenTelemetry. Good if your team already uses LangSmith for other projects.
pip install llama-index-callbacks-langfuse

from langfuse.llama_index import LlamaIndexInstrumentor
import os

os.environ["LANGFUSE_PUBLIC_KEY"] = "pk-..."
os.environ["LANGFUSE_SECRET_KEY"] = "sk-..."

instrumentor = LlamaIndexInstrumentor()
instrumentor.start()
# All queries auto-traced to Langfuse dashboard
📡 OpenTelemetry OSS standard
Industry-standard tracing protocol. Send traces to any OTLP backend: Jaeger, Grafana Tempo, Datadog, Honeycomb, etc.
pip install openinference-instrumentation-llama-index
pip install opentelemetry-exporter-otlp

from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider

# Export to any OTLP-compatible backend
exporter = OTLPSpanExporter(endpoint="http://jaeger:4318/v1/traces")

    tracer_provider=TracerProvider()

🔎 Langfuse Free tier
OSS LLM observability platform. Strong eval + tracing UI. Self-hostable. Good alternative to Phoenix if you need hosted tracing with evals.

LlamaCloud Observability

LlamaCloud is the managed cloud platform for LlamaIndex. It provides hosted tracing, pipeline management, and dataset curation through a web UI — ideal for teams that want observability without managing infrastructure.

What LlamaCloud provides
LlamaTrace
Hosted tracing dashboard — every query, retrieval, LLM call logged with full payloads
Pipeline UI
Visual editor for LlamaIndex pipelines — no-code configuration and testing
Dataset curation
Tag and export good/bad traces as evaluation datasets
LlamaExtract
Managed document extraction service (Topic 11)
LlamaParse hosted
Cloud PDF parsing — no local setup needed
Connect to LlamaCloud tracing
import os
from llama_index.core import set_global_handler

# Single line to enable LlamaCloud tracing
os.environ["LLAMA_CLOUD_API_KEY"] = "llx-..."

set_global_handler("llamacloud")

# All LlamaIndex operations now traced to cloud.llamaindex.ai
response = query_engine.query("What are our key risks?")
# → Visible immediately in LlamaCloud dashboard
Observability tools — when to use which
Local dev
LlamaDebugHandler — zero setup, prints to console
Team dev / staging
Arize Phoenix local — free, full UI, self-hosted, evals built in
Production (managed)
LlamaCloud or Langfuse — hosted, multi-user, persistent logs
Existing infra
OpenTelemetry → Datadog / Grafana / Honeycomb — if team already uses these
📊 The key metrics to monitor in production: query latency (p50/p95), retrieval score distribution, token cost per query, and answer quality scores (from evals in Topic 16). Without these, you're flying blind.
