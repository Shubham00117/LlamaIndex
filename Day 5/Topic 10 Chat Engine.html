Chat Engine — Multi-Turn Conversational Interface

The ChatEngine is the conversational counterpart to QueryEngine. It maintains conversation history so follow-up questions work naturally — "Who wrote it?" after "Summarize the report" correctly understands the context.

Chat demo — follow-up questions work
👤
What is LlamaIndex used for?
🤖
LlamaIndex is a framework for building RAG applications — it helps connect LLMs to your own data through indexing, retrieval, and query pipelines.
👤
Who made it?
← follow-up: "it" correctly resolves to LlamaIndex
🤖
LlamaIndex was created by Jerry Liu and the LlamaIndex team. It was originally called GPT Index.
Basic setup
# QueryEngine → one-shot Q&A
query_engine = index.as_query_engine()

# ChatEngine → multi-turn conversation
chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",  # recommended mode
    verbose=True
)

# Chat — remembers previous messages
resp1 = chat_engine.chat("What is LlamaIndex?")
resp2 = chat_engine.chat("Who made it?")  # uses history!

# Async version
resp = await chat_engine.achat("Tell me more")

# Streaming
resp = chat_engine.stream_chat("Summarize what we discussed")
for token in resp.response_gen:
    print(token, end="", flush=True)

# Reset conversation history
chat_engine.reset()
💡 QueryEngine = stateless, one Q&A at a time. ChatEngine = stateful, maintains full conversation history. Use ChatEngine for any user-facing chatbot.
#58

Chat Engine Modes

LlamaIndex provides multiple chat modes that handle conversation history differently. The right mode depends on whether you need RAG retrieval, plain LLM chat, or a hybrid approach.

condense_plus_context
Recommended
Condenses history into a standalone question, retrieves relevant context, then answers. Best for RAG chatbots.
condense_question
RAG
Condenses history + new question into one query, then retrieves. Simpler than condense_plus_context.
context
RAG
Retrieves context for every message regardless of history. Good when every turn needs fresh retrieval.
openai
Agent-style
Uses OpenAI function calling to decide when to retrieve. Smart but more LLM calls per turn.
best
Auto
Automatically selects the best mode based on configured LLM. Good default for quick setup.
simple
No RAG
Pure LLM conversation — no retrieval at all. Just uses chat history. Useful for testing.
Code — switching modes
# condense_plus_context — recommended for most RAG chatbots
chat_engine = index.as_chat_engine(chat_mode="condense_plus_context")

# context — fresh retrieval every turn
chat_engine = index.as_chat_engine(chat_mode="context")

# openai — function-calling agent style
chat_engine = index.as_chat_engine(chat_mode="openai")

# simple — no RAG, just conversation
chat_engine = index.as_chat_engine(chat_mode="simple")
🎯 Start with condense_plus_context — it handles follow-up questions correctly AND retrieves relevant context. It's the best balance of accuracy and efficiency.
#59

Chat Memory & Session Management

By default, chat engines use a simple in-memory buffer. For production, you need to manage memory carefully — LLM context windows are limited, and storing too much history increases latency and cost.

Memory types
ChatMemoryBuffer
Default. Stores raw message history. Truncates when token limit hit.
VectorMemory
Stores messages as embeddings — retrieves relevant past messages, not just recent ones.
SimpleComposableMemory
Combines buffer (recent) + vector memory (relevant past). Best for long sessions.
ChatMemoryBuffer with token limit
from llama_index.core.memory import ChatMemoryBuffer

# Limit memory to last ~3000 tokens of history
memory = ChatMemoryBuffer.from_defaults(token_limit=3000)

chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",
    memory=memory
)

# Inspect current memory
print(chat_engine.chat_history)   # list of ChatMessage objects
Multi-session with custom history
from llama_index.core.llms import ChatMessage

# Restore a session from database
saved_history = [
    ChatMessage(role="user",      content="What is RAG?"),
    ChatMessage(role="assistant", content="RAG stands for..."),
]

chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",
    chat_history=saved_history     # inject previous history
)

⚠️ Long chat history inflates token usage fast. Set a token_limit on your memory buffer and persist history in a database (Redis/Postgres) — not in-memory — for production sessions.

Chat Stores — Persistent Conversation History

In production, chat history must survive server restarts and be accessible across multiple instances. Chat stores persist conversation history to an external database keyed by session ID.

SimpleChatStore — file-based (dev)
from llama_index.core.storage.chat_store import SimpleChatStore
from llama_index.core.memory import ChatMemoryBuffer

# Persist to JSON file
chat_store = SimpleChatStore()

memory = ChatMemoryBuffer.from_defaults(
    token_limit=3000,
    chat_store=chat_store,
    chat_store_key="user_session_42"   # unique session/user ID
)

chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",
    memory=memory
)

# Save to disk
chat_store.persist(persist_path="./chat_history.json")

# Load back
chat_store = SimpleChatStore.from_persist_path("./chat_history.json")
Redis Chat Store — production
pip install llama-index-storage-chat-store-redis

from llama_index.storage.chat_store.redis import RedisChatStore

chat_store = RedisChatStore(
    redis_url="redis://localhost:6379",
    ttl=3600   # expire sessions after 1 hour of inactivity
)

memory = ChatMemoryBuffer.from_defaults(
    token_limit=3000,
    chat_store=chat_store,
    chat_store_key=user_id   # use actual user/session ID
)
FastAPI multi-user session pattern
from fastapi import FastAPI

app = FastAPI()
chat_store = RedisChatStore(redis_url="redis://localhost:6379")

@app.post("/chat/{session_id}")
async def chat(session_id: str, message: str):
    # Each session_id gets its own isolated memory
    memory = ChatMemoryBuffer.from_defaults(
        token_limit=3000,
        chat_store=chat_store,
        chat_store_key=session_id     # isolated per user
    )
    chat_engine = index.as_chat_engine(
        chat_mode="condense_plus_context", memory=memory
    )
    response = await chat_engine.achat(message)
    return {"reply": str(response)}
🔑 Always use a unique session ID as the chat_store_key — never share a key between users. In a real app this is typically the authenticated user ID or a UUID generated at session start.
QueryEngine vs ChatEngine — when to use which
ScenarioUseReason
One-shot document Q&A QueryEngine No memory needed, simpler, cheaper
User-facing chatbot ChatEngine Follow-up questions must reference prior turns
API endpoint, no session QueryEngine Stateless endpoints — caller manages context
Multi-turn research assistant ChatEngine Session context builds up across turns
Batch document processing QueryEngine Independent queries, no shared state needed
