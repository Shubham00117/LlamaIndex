Pydantic-Based Structured Output from LLMs

Force LLMs to return valid, typed JSON matching a Pydantic schema. The LLM can't return free text — it must populate your schema fields. Eliminates all parsing headaches.

Define schema → extract → get typed object
from pydantic import BaseModel, Field
from typing import List, Optional
from llama_index.core.program import LLMTextCompletionProgram
from llama_index.core.output_parsers import PydanticOutputParser

# 1. Define your schema
class Invoice(BaseModel):
    vendor_name:  str           = Field(description="Name of the vendor")
    invoice_date: str           = Field(description="Invoice date (YYYY-MM-DD)")
    total_amount: float         = Field(description="Total amount due")
    line_items:   List[str]    = Field(description="List of line item descriptions")
    is_paid:      bool          = Field(description="Whether invoice has been paid")

# 2. Create extraction program
program = LLMTextCompletionProgram.from_defaults(
    output_cls=Invoice,
    prompt_template_str="Extract invoice data from the following text:\n\n{text}",
    verbose=True
)

# 3. Run extraction — returns typed Invoice object
invoice: Invoice = program(text=raw_invoice_text)
print(invoice.vendor_name)    # "Acme Corp"
print(invoice.total_amount)   # 4250.00 (float)
Schema → Output visualization
Invoice Schema
vendor_name str
invoice_date str
total_amount float
line_items List[str]
is_paid bool
{ "vendor_name": "Acme Corp", "invoice_date": "2024-03-15", "total_amount": 4250.00, "line_items": [ "Software license", "Support fee" ], "is_paid": false }
✅ Always add Field(description=...) to every field. The LLM uses these descriptions to understand what to extract — without them, extraction quality drops significantly.
#62

Structured Prediction — Extracting Schemas from Documents

Use structured_predict directly on an LLM instance to extract structured data from any text in a clean one-liner pattern.

Using llm.structured_predict()
from llama_index.llms.openai import OpenAI
from llama_index.core.prompts import PromptTemplate
from pydantic import BaseModel

class ResearchPaper(BaseModel):
    title:    str
    authors:  List[str]
    year:     int
    abstract: str
    keywords: List[str]

llm = OpenAI(model="gpt-4o")

prompt = PromptTemplate("Extract structured info from:\n\n{paper_text}")

# Clean one-liner extraction
paper: ResearchPaper = llm.structured_predict(
    ResearchPaper,
    prompt,
    paper_text=raw_pdf_text
)

# Async version
paper = await llm.astructured_predict(ResearchPaper, prompt, paper_text=raw_pdf_text)
💡 llm.structured_predict() uses OpenAI function calling / tool use under the hood — it's more reliable than prompting for JSON and then parsing it manually.

LlamaExtract — Automated Schema-Based Extraction

LlamaExtract is a LlamaCloud API service for extracting structured data from documents at scale. You define a schema once, then extract from hundreds of PDFs without writing any pipeline code.

Flow
Define Schema
→
Upload PDFs
→
LlamaExtract API
→
Structured JSON
Usage
pip install llama-extract

from llama_extract import LlamaExtract

extractor = LlamaExtract(api_key="YOUR_LLAMA_CLOUD_KEY")

# Define extraction schema
class ContractData(BaseModel):
    parties:         List[str]
    effective_date:  str
    expiry_date:     Optional[str]
    contract_value:  Optional[float]
    governing_law:   str

# Create extractor agent with schema
agent = await extractor.acreate_agent(
    name="contract-extractor",
    data_schema=ContractData
)

# Extract from multiple files
results = await agent.aextract([
    "contract_a.pdf",
    "contract_b.pdf",
    "contract_c.pdf"
])

for r in results:
    print(r.data)   # typed ContractData object
⚡ LlamaExtract handles document parsing, chunking, and extraction automatically. Use it when you need to process many documents at scale without managing the full pipeline yourself.
#64

Text-to-SQL — Natural Language Over Databases

Let users query SQL databases in plain English. LlamaIndex generates the SQL query, executes it, and returns a natural language answer — no SQL knowledge required from the user.

Setup with SQLDatabase
from sqlalchemy import create_engine
from llama_index.core import SQLDatabase
from llama_index.core.query_engine import NLSQLTableQueryEngine

# Connect to any SQLAlchemy-compatible DB
engine = create_engine("postgresql://user:pass@localhost/mydb")
sql_db = SQLDatabase(engine, include_tables=["orders", "customers"])

# Create text-to-SQL query engine
query_engine = NLSQLTableQueryEngine(
    sql_database=sql_db,
    tables=["orders", "customers"]
)

# User queries in plain English
response = await query_engine.aquery(
    "What were the top 5 customers by revenue last month?"
)
print(response)
# Shows answer + the SQL it generated:
# SELECT c.name, SUM(o.amount) as revenue
# FROM orders o JOIN customers c ON o.customer_id = c.id
# WHERE o.date >= DATE_TRUNC('month', CURRENT_DATE - INTERVAL '1 month')...
NLSQLTableQueryEngine
Simpler setup. Good when table selection is static/known upfront.
SQLTableRetrieverQueryEngine
LLM selects which tables to query. Better for large schemas with many tables.
⚠️ Always use a read-only database user for text-to-SQL. The LLM could theoretically generate destructive queries — never expose write access.

Querying CSVs & Parsing Tables from Documents

Two common extraction patterns: natural language queries over CSV data, and extracting tables and charts from PDFs into usable structured formats.

Natural language over CSV files (#65)
from llama_index.experimental.query_engine.pandas import PandasQueryEngine
import pandas as pd

df = pd.read_csv("sales_data.csv")

query_engine = PandasQueryEngine(
    df=df,
    verbose=True   # shows generated pandas code
)

response = await query_engine.aquery(
    "What was the average revenue per region in Q3?"
)
# Internally generates: df[df['quarter']=='Q3'].groupby('region')['revenue'].mean()
Table & chart parsing from PDFs (#66)
from llama_parse import LlamaParse

# LlamaParse extracts tables as markdown
parser = LlamaParse(
    api_key="YOUR_KEY",
    result_type="markdown",
    # Tables become markdown tables:
    # | Product | Q1 | Q2 | Q3 |
    # |---------|----|----|----| ...
)
docs = await parser.aload_data("financial_report.pdf")

# Or use multimodal LLM to describe charts
from llama_index.multi_modal_llms.openai import OpenAIMultiModal

mm_llm = OpenAIMultiModal(model="gpt-4o")

# Pass chart image to multimodal LLM
response = await mm_llm.acomplete(

LlamaParse
Best for tables in PDFs — extracts as clean markdown. Handles merged cells, complex layouts.
PandasQueryEngine
Best for CSV/tabular data — generates and executes pandas code to answer questions.
Multimodal LLM
Best for charts/graphs — GPT-4o can read bar charts, pie charts, trend lines visually.
📊 Production pipeline for financial docs: LlamaParse → markdown tables → index into VectorStore → query naturally. Charts → GPT-4o vision → text description → index alongside text.
