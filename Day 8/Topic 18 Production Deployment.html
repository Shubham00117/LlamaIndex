FastAPI Integration & Async Best Practices

FastAPI is the production standard for serving LlamaIndex. All LlamaIndex async methods (aquery, achat) integrate cleanly with FastAPI's async routes.

Production FastAPI app skeleton
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from contextlib import asynccontextmanager
from llama_index.core import Settings

# ── Lifespan: build index ONCE at startup ────────────────────
query_engine = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    global query_engine
    # Load index from persistent store — do NOT rebuild on every request
    index = await load_index_from_storage()
    query_engine = index.as_query_engine(similarity_top_k=5)
    yield
    # Cleanup on shutdown

app = FastAPI(lifespan=lifespan)

# ── Request / Response models ────────────────────────────────
class QueryRequest(BaseModel):
    query: str
    session_id: str | None = None

class QueryResponse(BaseModel):
    answer: str
    sources: list[str]

# ── Standard query endpoint ──────────────────────────────────
@app.post("/query", response_model=QueryResponse)
async def query(req: QueryRequest):
    if not query_engine:
        raise HTTPException(status_code=503, detail="Index not ready")
    response = await query_engine.aquery(req.query)
    return QueryResponse(
        answer=str(response),
        sources=[n.node.metadata.get("file_name", "") for n in response.source_nodes]
    )

# ── Streaming endpoint (SSE) ─────────────────────────────────
@app.post("/query/stream")
async def query_stream(req: QueryRequest):
    streaming_engine = index.as_query_engine(streaming=True)
    response = await streaming_engine.aquery(req.query)

    async def generate():
        async for token in response.async_response_gen():
            yield f"data: {token}\n\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
Async best practices (#103)
Always use aquery/achat
Never call sync query() inside async routes — blocks the event loop
Build index at startup
Use lifespan context. Never rebuild the index per request.
Set concurrency limits
Use semaphores or request queuing to avoid overwhelming the LLM API
Handle timeouts
asyncio.wait_for(coro, timeout=30) on every LLM call
Use uvicorn workers
uvicorn app:app --workers 4 for multi-core utilisation
⚠️ The most common production mistake: calling sync methods in async routes. Always use aquery(), achat(), aretrieve(). Sync methods block the entire event loop and destroy throughput.

# For query caching — wrap query engine manually
from functools import lru_cache
import hashlib

query_cache = {}   # use Redis in production

async def cached_query(query: str) -> str:
    cache_key = hashlib.md5(query.encode()).hexdigest()
    if cache_key in query_cache:
        return query_cache[cache_key]
    response = await query_engine.aquery(query)
    query_cache[cache_key] = str(response)
    return query_cache[cache_key]
Rate limiting — protect your API (#107)
pip install slowapi

from slowapi import Limiter
from slowapi.util import get_remote_address
from fastapi import Request

limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter

# 20 queries/minute per IP
@app.post("/query")
@limiter.limit("20/minute")
async def query(request: Request, req: QueryRequest):
    return await query_engine.aquery(req.query)

# Concurrency limit with semaphore
import asyncio
semaphore = asyncio.Semaphore(10)  # max 10 concurrent LLM calls

async def throttled_query(q: str):
    async with semaphore:
        return await query_engine.aquery(q)
💰 Query caching can reduce LLM costs by 30–60% in production — many users ask the same or very similar questions. Semantic caching (embedding similarity) catches paraphrased duplicates that exact-match caching misses.

llama_deploy & llamactl — Workflow Microservices

llama_deploy converts LlamaIndex Workflows into scalable microservices with a REST API, message queue, and control plane. llamactl is the CLI to manage them.

Deploy a workflow as a microservice (#108)
pip install llama-deploy

# deploy.py
import asyncio
from llama_deploy import deploy_workflow, WorkflowServiceConfig, ControlPlaneConfig
from my_app.workflows import RAGWorkflow

async def main():
    await deploy_workflow(
        RAGWorkflow(timeout=60),
        workflow_config=WorkflowServiceConfig(
            host="0.0.0.0",
            port=8002,
            service_name="rag-workflow"
        ),
        control_plane_config=ControlPlaneConfig(
            host="0.0.0.0",
            port=8000
        )
    )

asyncio.run(main())

Security hardening (#110)
# 1. Input validation — never pass raw user input directly
from pydantic import BaseModel, validator

class QueryRequest(BaseModel):
    query: str

    @validator("query")
    def validate_query(cls, v):
        if len(v) > 2000:
            raise ValueError("Query too long")
        # Strip potential prompt injection attempts
        blocked = ["ignore previous instructions", "system prompt"]
        if any(b in v.lower() for b in blocked):
            raise ValueError("Invalid query")
        return v

# 2. API key authentication

Multi-tenancy — isolate per-user data (#112)
# Strategy 1: Metadata filtering (shared index)
def get_user_query_engine(user_id: str):
    return index.as_query_engine(
        filters=MetadataFilters(filters=[
            MetadataFilter(key="user_id", value=user_id)
        ])
    )

# Strategy 2: Namespace per tenant (Pinecone)
from llama_index.vector_stores.pinecone import PineconeVectorStore

def get_tenant_vector_store(tenant_id: str):
    return PineconeVectorStore(
        index_name="main",
        namespace=tenant_id   # fully isolated namespace
    )

# Strategy 3: Separate index per tenant (full isolation)
TENANT_INDEXES = {}

async def get_or_create_tenant_index(tenant_id: str):
    if tenant_id not in TENANT_INDEXES:
        TENANT_INDEXES[tenant_id] = await build_index_for_tenant(tenant_id)
    return TENANT_INDEXES[tenant_id]
Metadata filter
Simplest. Lowest cost. Risk: poor filter = data leak. Good for MVP.
Namespace (Pinecone)
Good isolation, same index. Production default for SaaS. Low overhead.
Separate index
Full isolation. Highest cost. Use only for enterprise/compliance requirements.
🔒 Multi-tenancy security is critical. Never return data from one tenant to another. Namespace isolation (Pinecone/Qdrant) is the safest production pattern — a bug in metadata filtering can expose data across tenants.
