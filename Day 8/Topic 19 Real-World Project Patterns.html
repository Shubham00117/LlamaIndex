Enterprise Document Q&A System

The core production RAG pattern. Ingests PDF/Word/HTML documents, chunks with metadata, retrieves with hybrid search + reranking, synthesizes with a scoped system prompt.

📄 PDFs/Docs
→

→
Pinecone (BM25 + Vector)
→
Cohere Reranker
→
GPT-4o + System Prompt
→
Answer + Sources
Key implementation decisions
Chunk size
512 tokens, 64 overlap. Store parent (2048) for auto-merging retriever.
Retrieval
Hybrid BM25 + Vector → top-20 → Cohere rerank → top-5 to LLM.
Metadata
doc_type, department, date, source_file on every chunk for filtering.
Ingestion pipeline
IngestionPipeline with Redis cache — only re-embeds changed documents.

🏢 Multi-Tenant (#117)

Pinecone namespace per tenant = full data isolation with one index. Auth middleware injects tenant_id from JWT — never trust user-provided tenant ID.

# Auth middleware extracts tenant from JWT
async def get_current_tenant(token: str = Depends(oauth2_scheme)):
    payload = jwt.decode(token, SECRET)
    return payload["tenant_id"]  # from verified JWT

@app.post("/query")
async def query(req: QueryReq,
                tenant_id: str = Depends(get_current_tenant)):

    # Scoped to tenant's namespace only
    vector_store = PineconeVectorStore(
        index_name="main",
        namespace=tenant_id  # ← isolation guaranteed
    )
    index = VectorStoreIndex.from_vector_store(vector_store)
    return await index.as_query_engine().aquery(req.query)

Automated report generation workflow (#120)

A Workflow that fans out to multiple data sources in parallel, gathers results, then synthesizes a structured report with Pydantic output.

# Workflow emits 3 parallel SourceEvents (see Topic 13 #78)
# Then collect_events(ev, [SourceEvent]*3) waits for all 3
# Then structured_predict(ReportSchema) produces the final output

class ReportWorkflow(Workflow):
    @step
    async def gather_rag(self, ev: StartEvent) -> SourceEvent:
        return SourceEvent(src="rag",
            data=await rag_engine.aquery(ev.topic))
    @step
    async def gather_sql(self, ev: StartEvent) -> SourceEvent:
        return SourceEvent(src="sql",
            data=await sql_engine.aquery(ev.topic))
    @step
    async def synthesize(self, ctx: Context, ev: SourceEvent) -> StopEvent:
        all_data = ctx.collect_events(ev, [SourceEvent] * 2)
        if not all_data: return None
        report = llm.structured_predict(ReportSchema, ...)
        return StopEvent(result=report)

Corrective RAG — self-correcting retrieval (#122)

The most sophisticated RAG pattern. After generating an answer, the system grades it. If quality is insufficient, it refines the query and retrieves again — up to a max iterations limit.

class GradeEvent(Event): answer: str; is_good: bool; query: str

class CorrectiveRAGWorkflow(Workflow):

    @step
    async def retrieve_and_answer(self, ctx: Context, ev: StartEvent) -> GradeEvent:
        nodes   = await retriever.aretrieve(ev.query)
        answer  = await synthesizer.asynthesize(ev.query, nodes)
        return GradeEvent(answer=str(answer), is_good=False, query=ev.query)

    @step
    async def grade(self, ctx: Context, ev: GradeEvent) -> Union[StartEvent, StopEvent]:
        tries = await ctx.get("tries", default=0)
        # Use LLM to grade the answer quality
        grade = await faithfulness_evaluator.aevaluate_response(response=ev.answer)

        if grade.passing or tries >= 3:
            return StopEvent(result=ev.answer)   # ✅ good answer or max retries

        # Refine query and retry retrieval
        await ctx.set("tries", tries + 1)
        refined = await llm.acomplete(f"Rephrase to find better evidence: {ev.query}")
        return StartEvent(query=str(refined))   # 🔄 retry
🎯 Corrective RAG is the most production-ready pattern for high-stakes use cases (legal, medical, finance). It trades latency for quality — 2–3× slower but faithfulness jumps from ~0.75 to ~0.92+.
