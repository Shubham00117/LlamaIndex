What is MCP & Why It Matters

MCP (Model Context Protocol) is an open standard created by Anthropic that defines a universal interface for LLMs to connect to external tools, data sources, and services. Think of it as USB-C for AI — any MCP-compatible tool works with any MCP-compatible LLM host without custom integration code.

#100

Using MCP Servers in LlamaIndex Agents

LlamaIndex can connect to any MCP server and automatically converts its tools into LlamaIndex-compatible FunctionTool objects that agents can use natively.

Connect to a local MCP server (stdio transport)
pip install llama-index-tools-mcp

from llama_index.tools.mcp import MCPToolSpec
from llama_index.core.agent import FunctionCallingAgent
from llama_index.llms.openai import OpenAI

# Connect to a local MCP server via stdio
mcp_spec = MCPToolSpec(
    server_params={
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
    }
)

# Get tools from the MCP server
tools = await mcp_spec.to_tool_list_async()
print([t.metadata.name for t in tools])
# ['read_file', 'write_file', 'list_directory', 'create_directory', ...]

# Use all MCP tools in an agent — automatically
agent = FunctionCallingAgent.from_tools(
    tools=tools,
    llm=OpenAI(model="gpt-4o"),
    verbose=True
)

response = await agent.achat("List all Python files in /tmp and summarize the largest one")
Connect to remote MCP server (SSE transport)
# Some MCP servers run as HTTP services (SSE transport)
mcp_spec = MCPToolSpec(
    server_params={
        "url": "http://localhost:8080/sse",
        "transport": "sse"
    }
)

tools = await mcp_spec.to_tool_list_async()

# Mix MCP tools with regular LlamaIndex tools
rag_tool = QueryEngineTool.from_defaults(
    query_engine=query_engine,
    name="search_docs",
    description="Search internal documents"
)

agent = FunctionCallingAgent.from_tools(
    tools=[*tools, rag_tool],  # MCP tools + RAG tool together
    llm=OpenAI(model="gpt-4o")
)

#101

Building Your Own MCP Server

You can wrap any Python function, API, or LlamaIndex component as an MCP server. Once built, it's instantly usable from Claude Desktop, Cursor, LlamaIndex, or any other MCP-compatible host.

Minimal MCP server in Python
pip install mcp

from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent
import asyncio

# Create server
server = Server("my-rag-server")

# Declare tools
@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="search_documents",
            description="Search internal company documents for relevant information",
            inputSchema={
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "Search query"}
                },
                "required": ["query"]
            }
        )
    ]

# Handle tool calls
@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "search_documents":
        # Use LlamaIndex query engine inside MCP tool!
        response = await query_engine.aquery(arguments["query"])
        return [TextContent(type="text", text=str(response))]

# Run via stdio
async def main():
    async with stdio_server() as (read, write):
        await server.run(read, write)

asyncio.run(main())
Expose LlamaIndex as MCP server — full pattern
# Expose your entire RAG system as an MCP server
# Any MCP client (Claude Desktop etc.) can now use your RAG

@server.list_resources()
async def list_resources():
    # Expose indexed documents as MCP resources
    doc_names = await get_all_document_names()
    return [
        Resource(
            uri=f"doc://{name}",
            name=name,
            description=f"Company document: {name}",
            mimeType="text/plain"
        )
        for name in doc_names
    ]

@server.read_resource()
async def read_resource(uri: str):
    doc_name = uri.replace("doc://", "")
    content = await load_document(doc_name)
    return [TextContent(type="text", text=content)]

stdio transport
Default. Server runs as subprocess. Best for local dev + Claude Desktop.
SSE transport
Server runs as HTTP service. Best for remote / production deployments.
Resources
Expose read-only data (docs, DB rows). LLM can request them as context.
Tools
Callable functions. LLM decides when to call them.
Prompts
Reusable prompt templates — expose via server for consistent LLM instructions.
🚀 The killer pattern: Build your LlamaIndex RAG system → wrap it as an MCP server → register in Claude Desktop. Now any Claude conversation can search your company's documents with zero extra code.
